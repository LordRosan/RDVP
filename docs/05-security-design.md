## 1. 设计范围

本文档定义 RDVP 的安全边界、身份认证、访问授权、二维码防伪、数据保护、附件安全、离线数据、审计日志、安全事件和密钥管理要求。

安全设计覆盖以下系统组成：

- HarmonyOS 移动端应用。
- 后端 API 服务。
- 数据库。
- 文件存储。
- 消息通知。
- 运维和部署环境。

## 2. 安全目标

RDVP 的安全目标如下：

- 确认访问者身份，防止未授权用户访问业务功能。
- 控制用户权限，防止越权查询、越权修改和越权审核。
- 校验设备二维码真实性，降低设备伪造和二维码伪造风险。
- 保护设备数据、故障数据、维修数据、附件和审计数据。
- 保证设备信息修改、故障接取、维修报告和复检等关键操作可追溯。
- 降低离线草稿、本地缓存、附件上传和消息推送带来的数据泄露风险。
- 记录异常行为和安全事件，支持后续审计和追踪。

## 3. 受保护资产

| 资产 | 示例 | 保护重点 |
| --- | --- | --- |
| 用户身份数据 | 账号、密码哈希、角色、权限 | 防止账号盗用和权限滥用 |
| 设备基础数据 | 设备编号、型号、厂商、位置、状态 | 防止伪造、误改和越权查看 |
| 二维码防伪数据 | 版本、随机标识、签名摘要 | 防止二维码伪造和重放 |
| 核验记录 | 核验结果、现场描述、位置、附件 | 保证记录真实可追溯 |
| 故障报告 | 故障类型、等级、描述、现场照片 | 防止篡改和泄露 |
| 维修数据 | 维修任务、维修报告、更换部件 | 保证维修过程可信 |
| 复检数据 | 复检结论、复检说明 | 保证重大故障闭环可信 |
| 附件数据 | 图片、报告附件、现场材料 | 防止非法上传、下载和传播 |
| 审计数据 | 操作日志、安全事件 | 防止删除、篡改和遗漏 |
| 密钥和凭证 | 签名密钥、访问令牌、配置密钥 | 防止泄露和滥用 |

## 4. 数据分级

| 级别 | 数据类型 | 处理要求 |
| --- | --- | --- |
| 公开数据 | 应用名称、公开版本信息 | 可公开展示 |
| 内部数据 | 普通设备摘要、非敏感配置 | 需要登录后访问 |
| 敏感数据 | 设备位置、故障详情、维修记录、附件 | 需要按角色授权访问 |
| 高敏感数据 | 密码哈希、签名密钥、访问令牌、防伪校验密钥 | 严格限制访问和存储位置 |
| 审计数据 | 操作日志、安全事件 | 追加记录，限制修改和删除 |

## 5. 身份认证

### 5.1 登录认证

用户访问业务功能前必须完成登录认证。后端负责校验账号、密码、账号状态和登录风险。

登录认证要求：

- 后端不得返回密码、密码哈希或密码相关内部字段。
- 密码只以哈希形式保存。
- 账号处于 `DISABLED` 或 `LOCKED` 状态时不得登录。
- 连续登录失败应触发频率限制或账号保护策略。
- 登录成功和失败均应写入安全事件或操作日志。

### 5.2 访问凭证

访问凭证用于移动端调用后端 API。

当前后端采用服务端会话令牌。登录成功后，后端生成不透明 Bearer token 并保存服务端会话状态，移动端不解析令牌内容。

凭证要求：

- 访问凭证必须具备过期时间。
- 移动端请求业务接口时使用 `Authorization: Bearer <token>`。
- 后端必须校验凭证有效性、过期状态和用户状态。
- 移动端可暂存访问凭证和必要用户信息，默认有效期为 7 天，不得暂存明文密码。
- 用户退出登录后，移动端应清理本地会话数据。
- 服务端应具备使访问凭证失效的能力。

### 5.3 密码策略

密码策略在用户管理功能中实现。

基础要求：

- 密码不得明文存储。
- 服务端使用 BCrypt 保存密码哈希，具体参数应随安全基线定期评估。
- 密码重置、账号启用、账号禁用等操作必须记录操作日志。
- 管理员重置密码后，应要求用户首次登录后修改密码。

## 6. 访问授权

### 6.1 授权模型

RDVP 使用基于角色的访问控制模型。用户通过角色获得权限，后端根据权限判断用户是否可以执行操作。

核心角色：

```text
SYSTEM_ADMIN
DEVICE_ADMIN
FIELD_OPERATOR
MAINTAINER
REINSPECTOR
SUPERVISOR_AUDITOR
READ_ONLY
```

基础权限划分：

| 角色 | 主要权限 | 说明 |
| --- | --- | --- |
| `SYSTEM_ADMIN` | `*` | 具备系统级管理和业务处理权限 |
| `DEVICE_ADMIN` | `ARCHIVE_DEVICE_READ`, `MGMT_ARCHIVE_CHANGE_REVIEW` | 查询设备档案，审核设备档案变更 |
| `FIELD_OPERATOR` | `ARCHIVE_DEVICE_READ`, `ARCHIVE_CHANGE_REQUEST_CREATE`, `OPS_DEVICE_VERIFY`, `OPS_FAULT_REPORT_CREATE` | 查询设备档案，提交档案变更申请、状态核验和故障报告 |
| `MAINTAINER` | `ARCHIVE_DEVICE_READ`, `OPS_REPAIR_TASK_ACCEPT`, `OPS_REPAIR_REPORT_CREATE` | 查询设备档案，接取维修任务并提交维修报告 |
| `REINSPECTOR` | `ARCHIVE_DEVICE_READ`, `OPS_REINSPECTION_CREATE` | 查询设备档案，处理复检任务并提交复检记录 |
| `SUPERVISOR_AUDITOR` | `ARCHIVE_DEVICE_READ`, `MGMT_AUDIT_LOG_READ` | 查询设备档案，查看操作记录和审计日志 |
| `READ_ONLY` | `ARCHIVE_DEVICE_READ` | 仅查询授权范围内的设备档案 |

### 6.2 授权边界

授权校验必须在后端完成。移动端隐藏或禁用无权限入口只用于界面控制，不作为安全依据。

后端应在以下位置执行授权校验：

- 查询设备详情。
- 提交设备核验记录。
- 创建设备信息变更申请。
- 审核设备信息变更申请。
- 创建故障报告。
- 接取维修任务。
- 提交维修报告。
- 提交复检记录。
- 上传和下载附件。
- 查询操作日志。
- 管理用户、角色和权限。

### 6.3 数据范围

权限校验不仅包含功能权限，还应包含数据范围。

数据范围示例：

- 只读人员只能查询被授权范围内的设备。
- 现场运维人员可以提交核验记录、档案变更申请和故障报告，但不能审核变更或处理维修任务。
- 维修人员只能查看可接取故障、自己接取的任务和关联报告。
- 设备管理员可以审核设备信息变更申请。
- 主管/审计人员可以查询操作日志，但不一定具备修改设备数据的权限。

## 7. 二维码防伪

### 7.1 二维码内容

二维码不保存设备敏感详情。二维码内容由可公开标识和防伪校验信息组成。

推荐结构：

```text
RDVP:<version>:<deviceCode>:<nonce>:<signature>
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `version` | 二维码格式版本 |
| `deviceCode` | 设备编号 |
| `nonce` | 随机标识 |
| `signature` | 服务端生成的防伪签名 |

### 7.2 校验流程

二维码校验流程：

1. 移动端扫描二维码。
2. 移动端将二维码原始内容提交至后端。
3. 后端解析二维码版本、设备编号、随机标识和签名。
4. 后端检查二维码状态、设备状态和过期时间。
5. 后端使用服务端密钥校验签名。
6. 校验通过后返回设备摘要或详情。
7. 校验失败时记录安全事件。

### 7.3 防伪约束

- 防伪签名密钥只存在于后端或安全密钥管理环境中。
- 移动端不得内置二维码签名密钥。
- `nonce` 必须具备唯一性。
- 二维码校验失败、签名错误、异常重复扫描应记录安全事件。
- 二维码版本应支持升级。

## 8. API 安全

### 8.1 传输安全

- 移动端与后端通信使用 HTTPS。
- 生产环境不得使用明文 HTTP 访问业务 API。
- 生产环境证书应具备有效期管理和替换机制。

### 8.2 参数校验

后端必须对所有请求参数进行校验。

校验内容包括：

- 必填字段。
- 字段长度。
- 枚举值范围。
- 时间格式。
- 经纬度范围。
- 业务对象是否存在。
- 当前状态是否允许执行目标操作。

### 8.3 状态流转校验

关键状态流转必须以后端规则为准。

受控状态包括：

- 设备状态。
- 设备信息变更申请状态。
- 故障报告状态。
- 维修任务状态。
- 维修报告结果。
- 复检结果。
- 离线同步状态。

### 8.4 频率限制

以下接口应具备频率限制：

- 登录。
- 二维码校验。
- 设备编号查询。
- 附件上传。
- 离线批量同步。
- 通知查询。

频率限制触发时返回 `RATE_LIMITED`。

### 8.5 错误响应

错误响应应提供稳定错误码和必要说明，不暴露内部堆栈、数据库结构、密钥路径、服务器路径或敏感配置。

## 9. 设备信息变更安全

设备主数据不能由普通用户直接修改。设备信息变更通过申请和审核流程完成。

安全要求：

- 变更申请必须记录申请人、申请时间、申请原因和变更字段。
- 变更内容必须保存修改前和修改后值。
- 审核通过后才更新设备主数据。
- 同一设备存在待审核变更申请时，后端必须拒绝新的变更申请。
- 设备变更审核通过并应用后，后端必须设置 12 小时变更冻结期并拒绝冻结期内的再次变更。
- 审核人、审核时间和审核意见必须保存。
- 审核通过、审核驳回和申请撤回必须记录操作日志。
- 审核人不得绕过后端接口直接修改设备状态。

## 10. 故障与维修安全

### 10.1 故障报告

故障报告创建后进入受控状态流转。

安全要求：

- 故障报告必须绑定设备和报告人。
- 故障等级、故障类型和设备状态更新由后端校验。
- 故障驳回必须记录驳回原因和操作人。
- 故障关闭必须经过合法状态流转。

### 10.2 维修接取

维修接取涉及并发控制和权限控制。

安全要求：

- 只有具备维修权限的用户可以接取。
- 后端必须校验维修人员状态和故障状态。
- 同一故障在同一时间只能存在一个有效维修任务。
- 接取成功和接取失败应具备可追踪记录。

### 10.3 维修报告

维修报告提交后由后端判断后续状态。

安全要求：

- 只有任务关联维修人员可以提交对应维修报告。
- 维修报告不得重复提交。
- 是否需要复检由后端根据故障等级和业务规则判断。
- 维修报告提交必须记录操作日志。

### 10.4 复检

重大故障或被指定复检的故障必须完成复检流程。

安全要求：

- 复检人员必须具备复检权限。
- 复检通过后才能关闭需要复检的故障。
- 复检不通过时，故障应重新进入维修处理流程。
- 复检结论必须记录操作日志。

## 11. 附件安全

### 11.1 上传控制

附件上传必须经过鉴权和校验。

上传控制要求：

- 限制文件类型。
- 限制文件大小。
- 限制单个业务对象的附件数量。
- 校验文件真实内容类型。
- 生成服务端存储键，客户端不得指定存储路径。
- 保存文件校验值。
- 上传结果写入附件元数据表。

### 11.2 下载控制

附件下载必须根据业务对象和用户权限判断。

下载控制要求：

- 用户必须登录。
- 后端校验附件是否存在。
- 后端校验附件关联业务对象。
- 后端校验用户是否有权限访问该业务对象。
- 文件下载日志应可追踪。

### 11.3 附件删除

附件删除应同时处理业务关联和实际文件内容。

删除控制要求：

- 删除操作必须鉴权。
- 已进入审计或归档流程的附件不应被普通业务删除。
- 删除操作必须记录操作日志。

## 12. 离线数据安全

移动端支持离线填写草稿，但离线数据不代表正式业务提交。

安全要求：

- 离线草稿必须标识本地状态。
- 离线草稿同步时，后端必须重新校验用户身份、权限和业务状态。
- 同步冲突不得由移动端单方面覆盖服务端数据。
- 包含敏感信息的离线草稿应进行本地保护。
- 用户退出登录后，应清理当前账号相关的本地临时数据或进行访问隔离。

离线状态：

```text
LOCAL_DRAFT
PENDING_SYNC
SYNCING
SYNC_FAILED
SYNCED
```

## 13. 日志与审计

### 13.1 操作日志

以下操作必须写入操作日志：

- 用户登录和退出。
- 设备信息变更申请提交。
- 设备信息变更审核。
- 故障报告提交。
- 故障报告驳回。
- 维修任务接取。
- 维修报告提交。
- 复检记录提交。
- 故障关闭。
- 角色和权限变更。
- 附件上传、下载和删除。

操作日志字段至少包括：

- 操作人。
- 操作类型。
- 操作对象类型。
- 操作对象 ID。
- 请求 ID。
- 操作时间。
- 操作前数据。
- 操作后数据。

### 13.2 安全事件

以下行为应记录安全事件：

- 登录失败次数异常。
- 账号被锁定。
- 无权限访问被拒绝。
- 二维码签名校验失败。
- 二维码异常重复扫描。
- 附件类型被拒绝。
- 离线同步发生状态冲突。
- 接口请求频率超过限制。

安全事件应具备严重程度：

```text
LOW
MEDIUM
HIGH
CRITICAL
```

## 14. 密钥与配置

### 14.1 密钥范围

RDVP 涉及以下密钥或敏感配置：

- 二维码签名密钥。
- 访问凭证签名密钥或会话密钥。
- 数据库连接凭证。
- 文件存储访问凭证。
- 推送服务凭证。

### 14.2 管理要求

- 密钥不得提交到 Git 仓库。
- 生产密钥不得写入移动端代码。
- 生产密钥不得写入公开配置文件。
- 不同环境应使用不同密钥。
- 密钥应支持轮换。
- 密钥泄露后应具备吊销和替换流程。

配置模板只能包含占位值，例如：

```text
.env.example
config.example.json
```

## 15. 隐私与数据最小化

移动端和后端应按业务需要采集数据。

数据最小化要求：

- 消息通知只包含必要摘要和业务标识。
- 二维码不包含设备敏感详情。
- 操作日志不记录明文密码、访问令牌和完整密钥。
- 附件访问不暴露底层存储路径。
- API 响应只返回当前用户权限范围内的数据。

### 15.1 移动端权限最小化

移动端申请系统权限应与业务场景一致。

权限使用要求：

- 扫描设备二维码时可申请相机权限，权限说明应明确指向二维码扫描用途。
- 通过系统图片选择器上传二维码图片时，应优先使用系统选择器返回的授权 URI，不扩大读取相册范围。
- 网络访问仅用于连接后端服务、同步业务数据和获取授权范围内的资源。
- 用户拒绝权限时，移动端应给出明确提示，并允许用户改用其他可用查询方式。

## 16. 部署安全

部署环境应隔离开发、测试和生产配置。

部署要求：

- 生产环境使用 HTTPS。
- 数据库不得直接暴露到公网。
- 文件存储访问应通过后端授权。
- 后端服务日志不得输出密钥、令牌、密码和完整敏感配置。
- 备份数据应纳入访问控制。

## 17. 安全验证

安全相关功能应覆盖以下验证点：

- 未登录访问业务接口返回 `UNAUTHORIZED`。
- 无权限访问业务接口返回 `FORBIDDEN`。
- 二维码签名错误返回 `QR_CODE_SIGNATURE_INVALID`。
- 同一故障并发接取只能成功一次。
- 重大故障维修后必须进入复检流程。
- 附件上传拒绝不允许的文件类型。
- 附件下载校验业务权限。
- 离线同步冲突返回明确错误。
- 操作日志记录关键业务动作。

## 18. 待确认问题

- 二维码签名算法和轮换策略。
